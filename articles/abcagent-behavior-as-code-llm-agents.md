## TL;DR

LLMエージェントには三つの壁がある──(a) 似たタスクでも挙動が大きく逸脱し、誤差が雪崩のように伝播する、(b) 同じ処理を入力だけ変えて再実行するたびにFM呼び出しコストが吹き上がる、(c) 長い実行コンテキストと複雑な計画をFMの指示追従能力だけに頼るには限界がある。

ABCAgentは「**行動即コード（Behavior as Code）**」という発想でこれらを一気に解く。エージェントの振る舞いをPythonコード（の中に必要に応じて神経関数を埋め込んだもの）で完全に指定し、実行時はそのコードが唯一の真実源となる。FMはプログラムを**設計・編集**するだけで、実行そのものは記号エンジンが確定的に駆動する。

結果は鮮やかだ。GSM-Symbolicで98.3%（神経エージェント97.3%, p=0.001）、τ²-telecomで71.9% Pass⁴（同47.4%, p=0.0001）。しかもGSM-Symbolicでは5.2倍の低レイテンシと7.0倍の低コストを達成する──92.6%のタスクが**プログラムの再利用**だけで解けるからだ。

> **Core insight**: 振る舞いを自然言語のプロンプトではなくコードで書くことで、再利用・確定性・検証可能性を一度に手に入れる。

## 背景：純神経エージェントの三つの壁

LLMを中心に据えたエージェント（以降「純神経エージェント」）は、開放タスクでの力強さを示してきた。しかし実運用では次の三つが壁になる。

### 壁1：挙動の逸脱と伝播

意味的に似たタスクでも、プロンプトの些細な違いやFMの非決定性で出力が大きく変わる。しかもエージェントは多段で動く──最初のステップの逸脱が後段に雪崩のように伝播し、取り返しのつかない状態に陥る。GSM-Symbolicの実験では、純神経エージェントはPass¹→Pass⁴で60.8%→47.4%と大きく崩れる。

### 壁2：コストとレイテンシの爆発

同じタスク族の異なる入力に対しても、FMを一から呼び出し直す。入力が変わっただけで論理は同じなのに、毎回全呼び出しを反復する──コストもレイテンシも入力数に線形に膨らむ。

### 壁3：コンテキストと指示追従の限界

実行が進むほどコンテキストは膨張し、FMの指示追従能力は劣化する。長いループをn回回すのにO(n)のコンテキスト消費と記憶の忘却が伴う。複雑な制御フローを自然言語で記述し、FMに正しく従わせ続けるのは本質的に困難だ。

## 方法详解：ABCAgentの中核

### 行動即コード（Behavior as Code）

ABCAgentはエージェントの振る舞いを**記号プログラム**（Pythonコード＋神経関数）で完全に指定する。ここで「完全に」とは、実行時にプログラム以外の何物も振る舞いを決定しない、という意味だ。FMはプログラムの**設計と編集**にしか関与しない。

```
![ABCAgentの全体構造](/images/abcagent-behavior-as-code-llm-agents/fig1.png)
```

この分離は「**エージェント設計**」と「**エージェント実行**」をきれいに切り離す：

- **設計フェーズ**：FM Designerがタスクを分析し、プログラムを生成・編集する
- **実行フェーズ**：記号エンジンがプログラムを確定的に実行する

### 神経記号の再帰パラダイム

ABCAgentのパラダイムは次の再帰式で表される：

$$\text{NS} = \text{Neural}[\text{Symbolic}[\text{NS}]]$$

- 外側の`Neural[·]`はFM Designer──プログラムを生成・編集する
- `Symbolic[NS]`は記号実行器──確定的に実行し、必要に応じて神経関数を呼ぶ
- 内側の`NS`は再帰──サブタスクを解くために再びFM Designerを呼べる

従来の`Symbolic[Neural]`（AlphaGoのMCTS＋NN）や`Neural[Symbolic]`（LLMが定理証明器を呼ぶ）とは異なり、ABCAgentでは**記号プログラムが中心**であり、FMはその管理者に徹する。

### 創作ループ（Authoring Loop）

新しいタスク族に直面したとき、ABCAgentは次のループでプログラムを作る：

1. **FM Designer**がタスク仕様と（あれば）先行実行のフィードバックからプログラムを生成
2. **記号実行器**でエンドツーエンド検証
3. 失敗すれば結果をFM Designerに返して改訂
4. **変異検査（Variant Check）**：FM Designerにタスクの変異体を提案させ、同じプログラムで解かせる。変異体に適応できなければ却下

```
![創作ループの流れ](/images/abcagent-behavior-as-code-llm-agents/fig2.png)
```

変異検査は**変形テスト（Metamorphic Testing）**に近い──「このプログラムが元タスクを解くこと」だけでなく「自然な変異体も解けること」を実行で確認するから、泛化性が宣言ではなく検証される。

### パラメータの再束縛とプログラム再利用

ここが効率の肝だ。プログラム内の入力値は**再束縛可能なパラメータ**として宣言される。同じタスク族の後続タスクでは、FMを呼ぶことなく**値だけを差し替えて再実行**できる。

具体例：GSM-Symbolicの最初の問題でプログラムPを作ったとする。次の問題では、Pのパラメータを新たな数値に束縛して実行するだけ──FM呼び出しゼロ、レイテンシは数秒、コストもほぼゼロだ。

実験ではGSM-Symbolicの92.6%、augmented GAIAの20.1%がこの「無料再利用」で解けた。

### 状態と進捗の構造化管理

純神経エージェントでは状態はフラットなテキストコンテキストに押し込まれる。ABCAgentでは：

- **短期知識**はプログラム変数──型があり、解釈の余地がない
- **実行進捗**は構造化コールスタック──ループや関数に入るたびに新しい実行フレームと局所スコープが作られる
- **制御フロー**はコードが決定──n回のループにO(n)のコンテキスト不要、FMに「あと何回？」と聞く必要もない

## 実験結果

### 主結果：6ベンチマークでの比較

```
![主結果の比較](/images/abcagent-behavior-as-code-llm-agents/fig3.png)
```

| ベンチマーク | 純神経 | ABCAgent | p値 |
|---|---|---|---|
| GAIA base (165) | 76.4% | 72.7% | 0.377 |
| GAIA augmented (378) | 59.5% | 57.1% | 0.281 |
| GSM-Symbolic (5000) | 97.3% | **98.3%** | **0.001** |
| τ²-telecom Pass⁴ (114) | 47.4% | **71.9%** | **0.0001** |
| τ²-airline Pass⁴ (50) | 58.0% | 60.0% | 1.000 |
| WorkArena-CF (42) | 58.3% | 64.3% | 0.453 |

読み取りの要点：

- **GAIA系**では統計的に同等──「行動即コード」が精度を犠牲にしていない
- **GSM-Symbolic**で有意に上回る──記号化された数学タスクで確定性実行の強さが光る
- **τ²-telecom**で圧倒的──複雑な制御フローと多段評価で、純神経の崩れ（60.8%→47.4%）に対しABCAgentは81.6%→71.9%と安定
- **WorkArena-CF**で各ループ長において正しいレコードをより多く書く

### 効率：再利用が効く場面での爆発的改善

| ベンチマーク | コスト効率 | レイテンシ加速 |
|---|---|---|
| GAIA base | 0.90× | 0.85× |
| GAIA augmented | **1.24×** | **1.33×** |
| GSM-Symbolic | **6.97×** | **5.21×** |
| τ²-telecom | **12.93×** | **9.50×** |
| τ²-airline | **5.66×** | **4.08×** |

GSM-Symbolicで7倍のコスト効率──その源泉は92.6%のタスクがプログラム再利用で無料解決されること。再束縛＋検証の呼び出しはタスクあたり約3.6秒、GSM-Symbolic 5000タスク全体でわずか\$18.01だ。

τ²-benchでは、作った戦略プログラムが**3回未満の評価パス**で制作コストを回収する（telecom 1.44回、airline 2.36回）。

## 考察：何が効いているのか

### アブレーション──三つの構成要素の寄与

```
![アブレーション結果](/images/abcagent-behavior-as-code-llm-agents/fig4.png)
```

| 設定 | Aug. GAIA L1 | GSM-Sym. | WA-CF |
|---|---|---|---|
| 純神経 | 62.0% | 99.7% | 76.5% |
| ABCAgent（完全） | 58.9% | 99.1% | 83.3% |
| − 再利用・再束縛 | 62.8% | 99.4% | 77.8% |
| − 変異検査 | 56.6% | 99.8% | 68.8% |

- **再利用・再束縛**が効率の主因──GSM-Symbolicでは96%が無料解決、コスト効率11.91×
- **変異検査**は泛化性の保証──外すとWorkArena-CFでSRが83.3%→68.8%に落ち、誤ったフィールドに書き込むプログラムが混入する
- 要素は**非加算的**──再利用だけあっても再束縛が無いと、かえって高コストになる場合がある

### プログラム移行分析──前方と後方の泛化

GSM-Symbolicで、過去に作ったプログラムを将来のタスク（前方）と過去のタスク（後方）に適用した：

- **後方泛化**：再利用0.963 vs 対照0.826（p<10⁻⁴）──プログラムが過去タスクにも強い後方互換性を持つ
- **前方泛化**：再利用0.958 vs 対照0.842（p<10⁻⁴）──将来タスクにも有意に泛化
- Aug. GAIAでは前方泛化は有意でない──新しい変異体が新しい要求を導入する場合、既存プログラムだけでは追いつかない

### 「過去の実行を見せるだけでは不十分」

純神経エージェントに過去の実行転写を注入しても、τ²-telecomのPass¹は0.603→0.671にしか改善しない。同じ転写をABCAgentに与えると0.789に跳ね上がる。

この差は**情報の形式**に由来する──自然言語の転写は参考程度にしかならないが、実行可能なプログラムは**振る舞いを規定**する。散文とコードの差が、そのまま泛化力の差になる。

### 限界──万能ではない

- **一次性タスクでは高コスト**──WorkArena L1でコストは純神経の2.4倍。再利用の恩恵がない場面では創作オーバーヘッドが重い
- **単一モデル族**──全実験がClaude Sonnet 4.6で行われており、より小さいモデルでの結果は未確立
- **評価ノイズ**──augmented GAIA L1で19.4%のタスクが兄弟順序だけで結果が変わり、同一設定の成功率が33-55/88の間で揺れる
- **保存プログラムの誤伝播**──検証をすり抜けたプログラムは、複数入力で同じ誤りを反復し得る

## 関連研究

### 神経記号AIの系譜

| パラダイム | 構造 | 代表 |
|---|---|---|
| Symbolic[Neural] | 記号が神経を呼ぶ | AlphaGo (MCTS+NN) |
| Neural[Symbolic] | 神経が記号を呼ぶ | LLM→定理証明器 |
| Neural∥Symbolic | 並行協調 | 知覚＋推論 |
| **Neural[Symbolic[NS]]** | **再帰的神経記号** | **ABCAgent** |

ABCAgentの再帰性は新しい──記号プログラムが中心にあり、FMはその管理者であり、さらにその内部で再帰的にNSを呼べる。

### コード生成・実行エージェントとの差

- **CodeAct**等は瞬時のコード片を生成して破棄する──制御フローはFMが担当、変数スコープの昇格なし
- **Voyager等のスキル誘導**は下位プログラムを再利用するが、トップレベルの制御は依然FM
- **DSPy / AFlow**はオフラインでパイプラインを探索する──実行時の動的適応なし
- **ABCAgent**はプログラムが制御フローを完全に決定し、パラメータ再束縛でタスク族横断的に再利用し、変異検査で泛化性を実行確認する

### 並行作業

Qi et al. (2026)の「LLM-as-code」もプログラムに制御を委ねるが、ABCAgentは**タスク族横断の再利用**（再束縛＋泛化性検査）に重点を置く点で異なる。Pedada et al. (2026)はセッション横断の再利用を図るが、パラメータ宣言や泛化性の実行検査を持たない。

## まとめ

ABCAgentの主張は単純で強力だ──**エージェントの振る舞いをコードで書け**。プロンプトに散文で指示するのではなく、実行可能なプログラムで完全に指定する。そうすれば：

1. **確定性**：実行は記号エンジンが駆動し、FMの非決定性に振り回されない
2. **効率**：同じタスク族ではプログラムを再利用するだけでFM呼び出しゼロ──GSM-Symbolicで7倍のコスト削減
3. **泛化性**：変異検査が「プログラムは変異体も解けるか」を**実行で確認**する──宣言ではなく検証
4. **構造化状態**：変数は型付き、進捗はコールスタック、制御フローはコード──長期実行での漂白や忘却を防ぐ

当然、万能ではない。一次性タスクでは創作コストが重く、小さいモデルでの評価も未だ空白だ。しかし「振る舞いを書く」という方向性は、LLMエージェントの実運用における再現性とコストの両方に一本の筋を通す。散文で頼むか、コードで決めるか──その選択が、エージェントの信頼性を分ける。
