## TL;DR

- リポジトリ規模のissue解決では、コードの正しさだけでなく「タスク制約を守り続けること」「ツール応答に反応すること」が効く。ところが著者らの診断分析では、エージェントは**文脈内にすでにある情報を行動に活かせない**場面で繰り返し失敗していた
- 興味深いのは、該当箇所にリマインダー（助言テキスト）を差し込むだけでこの種のエラーが実際に減ること。つまりモデルは「言われれば直る」のに、言われないまま失敗する
- しかし推論時リマインダーには、構築コスト・コンテキスト消費・足場（scaffold）への依存という代償がつく。OPRDはこの「言われれば直る」挙動を**訓練時にだけ利用して重みへ移す**ことを目指す
- 手法の核は2つ。最終テスト診断を軌跡全体へ伝える**Global Reminder**と、観測直後の1決定だけに効く**Turn-local Reminder**からなるスコープ付き監督。そして検証結果による**ルーティング**：成功ロールアウトは自己模倣、失敗ロールアウトはリマインダー条件付きの教師からTop-100リバースKLで蒸留
- Qwen3.5-4BでSWE-bench 3種の平均解決率が**+11.3pt（36.6→47.9）**、過程エラーイベント数は**446→222（-50.2%）**。9Bでも+11.5pt。推論時はリマインダー完全なし

## 背景：あるのに使わない

長期コーディングエージェントの評価は、SWE-bench系に代表される「最終パッチが実行検証を通るか」という結果ベースの指標に支えられてきた。一方で実際の失敗を眺めてみると、破綻の多くはもっと手前にある。タスクが許している変更範囲を超えてパッチを広げる。ツール応答に明示されたエラーを見過ごす。編集後に検証を回さずに完了宣言する。いずれも、**必要な情報はすでに文脈内にある**のに、それが行動に反映されないタイプの失敗だ。

著者らはこの直感を定量した。SWE-rebench V2検証セットから200課題を取り、Qwen3.5-4Bに同一設定でロールアウトさせる。決定論的ルールでツール・実行の明示的失敗を拾い、残りの文脈依存イベントはGPT-5.4に軌跡全体を見せて分類した。結果、エラーイベントは4つのカテゴリーに整理できる。

- **Tool-Feedback Recovery**：明示的なツール・実行フィードバックへの追従
- **Scope and Source Grounding**：根拠に基づく特定と、変更スコープの遵守
- **Scenario-Condition Reasoning**：条件分岐・フォールバックなどシナリオ別の挙動把握
- **Post-Edit Control and Validation**：編集後の拡張抑制と検証の完遂

そして決定的な観察が2つ目のロールアウトにある。同じ課題を再実行し、実行時のリマインダー機構（観測を検査し、次の行動の前に助言を挿入する）を有効にすると、**4カテゴリーすべてでエラーイベント数が減った**。モデルの能力不足ではなく、注意の向け方の問題だというわけだ。

ただしこの結果をそのまま運用に持ち込むのは難しい。実行時リマインダーは、差し込み箇所の判定を毎回行う構築コスト、コンテキストの余分な消費、そして特定のエージェント足場への依存を伴う。教師あり模倣や実行結果最適化といった既存の訓練信号も、Pass/Failという疎な結果は与えるものの、「どの制約が軌跡を通じて保持されるべきか」「どの観測が次の決定を導くべきか」という過程レベルの情報は与えない。

そこで本論文の問いはこうなる。**訓練時にだけスコープ付きの修正情報を与え、推論時にはリマインダーなしで動くエージェントにできるか**。

この問いにオンポリシー蒸留の枠組みで取り組むには、障害が2つあった。第一に、訓練時の修正情報には時間スコープの異なるものが混在する。局所的な修正を長い文脈に埋もれさせれば希釈され、無関係な決定へ伝播させれば汚染される。スコープの明示が必要になる。第二に、指示追従の適応を受けていないモデルは制約やフィードバックを無視しかねず、リマインダー付きの教師がそもそも信頼できる蒸留目標を産めない。こちらは下準備の問題だ。OPRDはこの2つにそれぞれ明示的に答える。

## OPRDの方法

![OPRDの全体像](/images/oprd-on-policy-reminder-distillation/fig1.png)

### 全体像

パイプラインは3段に組まれている。まずベースモデルに**Coding SFT**（検証済み成功軌跡8,000本：SWE-rebench V2から7,262本、Multi-SWE-RLから738本）でリポジトリ理解・ツール操作・編集の基礎を固め、続く**IF SFT**（リマインダー追従例2,000例）で制約とフィードバックへの応答性を鍛える。ここで得たIFチェックポイントを**教師と生徒が共有の初期値**とする。

訓練ループでは、生徒が4,000課題（SWE-rebench V2 3,630＋Multi-SWE-RL 370）のプールからリマインダーなしでロールアウトし、実行検証器が成功／失敗を判定する。成功した軌跡は自己模倣の標的へ、失敗した軌跡はリマインダー構築を経て教師による再評価へ、と**結果ベースでルーティング**される。教師は訓練中に段階的に生徒のパラメータをコピーして更新され、推論時には生徒だけが残る。

### Multi-Scope Reminders：スコープを2つに分ける

![Multi-Scope Reminderのスコープ](/images/oprd-on-policy-reminder-distillation/fig2.png)

失敗軌跡から修正情報を構築するとき、OPRDは時間スコープで2種類に分ける。

**Global Reminder（r^G）**は、最終テストの診断を軌跡レベルの指針へ変換したもの。パッチの適用状況、通過／失敗テストの内訳、触れたファイル、原因らしい失敗シグナル（インターフェース・引数・シグネチャ系を優先）を要約し、再試行の軌跡を通じて参照可能にする。参照パッチは当然明かさない。**Turn-local Reminder（r^L_k）**は観測o_kに錨を打ち、直後のassistant行動a_{k+1}の評価時にだけ見える。以降のターンには伝播しない。担当するのは先の4機能カテゴリーだ。

この分離が効く理由は、単一スコープの両極端がそれぞれ失敗するからだ。すべてを軌跡全体のプロンプトに寄せれば、長い文脈の中で局所的な修正が希釈される。逆に局所フィードバックを以降すべてのターンに垂れ流せば、相互作用の状態が変わった後の無関係な決定まで汚染する。**持続すべき制約には軌跡スコープを、1決定だけの修正には観測スコープを**与えるという設計は、過程監督の設計一般に転用できる考え方に見える。

構築の実装も慎重だ。32の細粒度ルビック項目（決定論的ハードルール10＋モデル判定の文脈戦略22）を4クラスへ集約し、実行時にはまずハードルールを最新のツール応答と照合、残りを判定モデルがconfidence 0.90以上で採択する。ファミリーごとの上限、課題ごとの予算、重複除去、参照パッチを明かす内容の排除を経て、候補が全滅すれば**挿入しない**（フォールバックカテゴリなし）。曖昧な助言で水増しされない設計だ。

### 2段階コールドスタート：蒸留の前提を作る

Coding SFTだけを施したモデルは、コーディング能力があっても文脈内の制約やフィードバックを無視しうる。教師がリマインダーに従えなければ、リマインダー条件付きの蒸留目標そのものが揺らぐ。そこでIF SFTを第2段に置き、リマインダー追従率という孤立指標で検証したところ、ベース45.8 → Coding SFT後49.3 → IF SFT後**77.1**と、27.8ptの跳ね上がりが観測された。この「リマインダーに従える教師」がOPRDの開始条件になる。

### 結果ベースのルーティングとリバースKL

検証器が与えるのは二値結果のみで、細粒度の信用割当てはない。OPRDの割り切りは明快だ。**成功ロールアウトは、現在の方針がその課題を解けるという実行証拠**だから、assistantトークン全体にautoregressiveな自己模倣損失を直接かける。失敗ロールアウトに同じ目的をかけると誤った決定の尤度を上げてしまうので、別扱いにする。

失敗側の処理がこの手法の肝だ。教師は軌跡を再サンプリングしない。**生徒が生成したのと同じトークン前置き**を、リマインダー付きの文脈で再評価する。Global Reminderは全ターンで可視、Turn-local Reminderは錨の観測の直後の行動評価にだけ注入される。これにより蒸留目標は常に「現在の方針が訪れる状態」に整合し続ける。

損失はTop-100リバースKL（温度T=1.0）。サポートの選択は生徒・教師のlog確率のpointwise最大を重要度スコアとし、上位100トークンの共通サポート上で両分布を正規化してから計算する。リバースKLは**生徒が高確率を割り当てた位置のズレを優先して罰する**性質があり、自信を持った誤りへの訂正が効きやすい。合成は `L_OPRD = λ+·E[L_pass] + λ−·E[L_fail]` で、最良設定は1:1。

教師は勾配降下で学習しない。代わりに訓練進捗の20/40/60/80%の時点で生徒のパラメータをコピーする**定期リフレッシュ**（計4回）を用いる。凍結教師は進化する生徒の訪れる状態からずれ、共有パラメータは目標の安定性を失う、という中間の取り方が最も効いた。

### 推論時

訓練後、デプロイされるのは生徒のみ。教師も、リマインダー構築モジュールも、すべてのリマインダーも除去される。ベースラインと同じClaude Code足場、温度1.0、top-p 0.95、最大200ターンという設定で動く。

## 実験結果

### 主結果：リマインダーなしで+11.3pt

![主結果](/images/oprd-on-policy-reminder-distillation/fig3.png)

| 訓練構成（Qwen3.5-4B） | Verified | Pro | Multilingual | 平均 |
|---|---|---|---|---|
| Base | 50.4 | 24.2 | 35.3 | 36.6 |
| + Coding SFT | 53.6 | 25.6 | 38.7 | 39.3 |
| + Coding SFT → IF SFT | 55.8 | 26.7 | 42.3 | 41.6 |
| + Coding SFT → OPRD（IF SFTなし） | 58.4 | 28.3 | 46.3 | 44.3 |
| + Coding SFT → IF SFT → OPRD（完全版） | **61.2** | **30.5** | **52.0** | **47.9** |

| 訓練構成（Qwen3.5-9B） | Verified | Pro | Multilingual | 平均 |
|---|---|---|---|---|
| Base | 59.6 | 32.3 | 41.3 | 44.4 |
| + Coding SFT → IF SFT → OPRD（完全版） | **70.0** | **40.9** | **56.7** | **55.9** |

すべての行が**リマインダーなし推論**の結果である点が重要で、改善はtest-time注入に依存していない。4Bでは平均+11.3pt、9Bでも+11.5ptとスケールを跨いで効く。伸びはMultilingualで最も大きく（4Bで35.3→52.0の+16.7pt）、ツール応答とファイル横断の文脈を要する課題への効き方と噛み合う。IF SFTを抜いたOPRDは平均3.6pt（9Bでは2.6pt）落ちる。冒頭の診断通り、蒸留の前提を作る段階として効いている。

### 消融：設計選択の寄与

![消融と診断](/images/oprd-on-policy-reminder-distillation/fig4.png)

**ルーティングとKL方向**。全ロールアウトに一括で同じKL目的を適用するOPSD対比では、forward KLで45.2、reverse KLで46.0。結果ルーティングを入れるとforward 46.7、reverse 47.9と、固定KL方向で+1.9pt。「成功は自己模倣、失敗は蒸留」という割り振り自体が効く。**KLサポートと温度**はTop-100・T=1.0が最良（全語彙T=0.6で46.5、T=1.5で47.1）。疎なサポートで十分で、温度は教師の選好と有用な代替案のバランスを取る中間値が効く。**損失バランス**はλ+:λ−=1:1が全ベンチマークで最高。失敗側に寄りすぎると発見済みの成功挙動の保持が弱まり、成功側に寄りすぎると過程監督が使われなくなる。

**Reminder追従率**の3段階比較（45.8→49.3→77.1）は、IF SFTの寄与をエンドツーエンドの解決率から切り離して測っている。カテゴリー別ではScope and Source Groundingが46.3→76.7と最大の改善で、「根拠に基づいて特定・変更する」挙動への指示応答性が特に鍛えられる。

**過程エラー削減**。同じ200課題・同一推論設定で、4カテゴリー合計のエラーイベント数はBase 446 → Coding SFT 378 → OPRD **222**。カテゴリー別削減率は43.1〜58.0%で、Post-Edit Control and Validationの減少が最大。タスク解決率と中間過程の品質が同時に改善している。

そのほか、教師リフレッシュは4回が全ベンチマークで最良（非単調）、ReminderスコープはGlobal単独・Turn-local単独でも全チェックポイントを改善し併用が最高、機能カテゴリーは4種すべてがreminder-free超えでPost-Edit系が最強、と異常のない消融結果が揃う。

## 考察

**蒸留の品質は教師の指示応答性で決まる**。本論文で個人的に最も示唆的なのは、IF SFTを挟む挟まないの差（3.6pt）と追従率77.1%の一連の結果だ。リマインダー条件付き蒸留は「教師がリマインダーに従って賢くなる」ことを暗黙の前提とする。この前提が成立していない状態で蒸留しても、目標分布は頼りない。特権情報を活かした教師設計において、**指示追従の下準備は性能改善ではなく前提の構築**だという切り分けは、他の文脈蒸留にもそのまま効く視点だと思う。

**前置きを固定する再評価の妙**。失敗軌跡の処理で教師に再サンプリングさせない設計は、on-policy性の維持という点で本質的だ。教師が自分の好む状態から目標を作ると、生徒の訪れる分布から外れた目標になりやすい。同じ前置きをリマインダーだけ変えて見直すことで、「この状態で、この注意を払えば、どう動くべきか」という条件付きの差分だけが蒸留される。リバースKLが生徒の高確率トークンを優先的に罰する性質と合わせ、自信満々の誤りを狙って直す構造になっている。

**二値検証器でどこまで行けるか**。ルーティングの信号は成功／失敗の1ビットで、失敗軌跡内のどの決定が悪かったかは分からない。それでも+1.9ptの差がつくのは、Minimalな信用割当て（失敗を模倣しない、成功は模倣する）だけでも自己蒸留より安全だからだろう。一方で失敗側の监督品質はリマインダー構築パイプライン（ハードルール＋判定モデル）の上限に依存する。判定モデルの精度が教師の目標分布の天井になるという構造は、スケールさせたときにどこまで付いていけるか気になるところだ。

**シリーズの文脈で**。このブログでも取り上げてきた「取り出したのに読まない」は、検索拡張LLMが眼前の証拠を使わず古い答えを返す話だった。OPRDの診断はそのエージェント版とも言える。**情報は文脈にあり、行動は文脈に従わない**という同型の失敗が、RAGでもコーディングでも観測される。ただしOPRDはそれを推論時の文脈操作でなく重みへの内在化で解く。またPTAやAMPLE-Mathで見たオンポリシー蒸留の系譜に、Privileged Informationを置く場所（どのスコープに、どのターンだけに）を明示するという新たな設計軸を加えた形になる。Priming Base ModelsがミッドトレーニングでSWEエージェントの下地を作ったのに対し、OPRDはSFT後の過程監督を蒸留で内在化するという、段階としては後ろ側に位置する話だ。

**限界**も見えている。エラー診断と文脈依存イベントの分類にGPT-5.4を使っており、診断自体のノイズは制御実験の解釈に影響しうる。タスクプールがSWE-rebench V2由来に偏る中での汎化は、SWE-bench 3種への転移で一応裏付けられているが、より遠い分布での追試は欲しい。4カテゴリーの分類が網羅でない可能性（分類されない失敗タイプ）や、リマインダー構築コストが訓練時とはいえゼロではない点も、実用の際には勘定に入れる必要がある。

## 関連研究

- **オンポリシー蒸留**：GKD（Agarwal et al., ICLR 2024）が自己生成ミスからの学習を形式化し、MiniLLM（Gu et al., ICLR 2024）がリバースKLを、DistiLLM（Ko et al., ICML 2024）がskew KLを導入した。エントロピー考慮やブラックボックス拡張も続いている。OPRDはこの系譜に「結果ルーティング」と「スコープ付き特権情報」を加える
- **文脈・特権情報蒸留**：Learning by Distilling Context（Snell et al., 2022）やOPCD（Ye et al., 2026）は文脈由来の挙動を重みへ移す先行例。Privileged Information Distillation（Penaloza et al., 2026）は訓練時のみの情報を扱う。OPRDの差分は、修正情報に**明示的な時間スコープ**を持たせた点と、それを長期コーディングの過程監督に束ねた点
- **SWEエージェントの訓練**：SWE-Gym、SWE-RL、SWE-smith、R2E-Gymらが軌跡・検証器・環境生成でスケールしてきた。これらは結果ベースの信号が中心で、OPRDは過程レベルの修正を蒸留経路で補う
- **実行時の適応**：ReAct、Reflexion、Self-Refine、CRITICは観測やセルフクリティックを行動に反映する。OPRDはその反映挙動を訓練時に内在化することで、推論時の機構を不要にする方向に立つ

## まとめ

OPRDは「文脈にある情報を使えない」という長期コーディングエージェントの過程的失敗から出発し、それを訓練時だけのリマインダーで教師に与え、重みへ移す。鍵となった設計は3つ。持続制約と局所修正を分けた**Multi-Scope Reminder**、成功を自己模倣・失敗を蒸留へ振り分ける**結果ベースのルーティング**、そして蒸留の前提としての**2段階コールドスタート**。Qwen3.5-4Bで平均+11.3pt、過程エラー半減、9Bでも再現という結果は、リマインダーという「足場の知能」を「重みの知能」に変換できるという命題への手応えだ。

推論時には何も足さない。それでいて足場に頼った頃の過程品質に近づく。エージェントの信頼性を上げる手段として、文脈を操作する方向と重みを鍛える方向があるとき、後者の割合をどこまで上げられるか。本論文はその一つの実測点を与えてくれる。
