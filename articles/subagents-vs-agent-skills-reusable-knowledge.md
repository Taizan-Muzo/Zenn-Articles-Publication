# 知識は使い方で決まる──サブエージェントとスキルの実行方式が長期タスクの性能を分ける仕組み

> **Piriyakulkij, Lawrence, Curth, Karmalkar, Prasad (2026)** "Subagents vs Agent Skills: Executing Reusable Knowledge for Long-Horizon Agentic Tasks" arXiv:2609.09233

## TL;DR

LLMエージェントに再利用可能な知識をどう実行させるか──その選択が、長期タスクの成否を大きく左右する。本稿は、**Agent Skill実行**（知識を主コンテキストに読み込む）と**Subagent実行**（知識を独立したコンテキスト窓で実行する）の2方式を体系的に比較し、以下を実証した：

- スキルパッケージが**手続的知識＋明示的な入出力契約**を持つとき、Subagent実行がAgent Skill実行を上回る
- コンテキスト圧力（ダミーツール数）が増大するにつれ、Subagent実行の劣化がより緩やか
- 代价として、Subagent実行は総トークン消費が1.3〜1.8倍に増加する
- **ハイブリッド実行**（ルーティングはAgent Skill、葉スキルはSubagent）が一貫して最も優れる

核心の洞察は、**再利用可能な知識の効用は、その内容だけでなく、組織化と呼び出しの方式にも依存する**ということだ。

## 背景：再利用可能な知識をどうエージェントに与えるか

### 知識注入の三世代

LLMエージェントに外部知識を与える方法は、大きく三つの時代を経てきた。

| 世代 | 方式 | 特徴 |
|------|------|------|
| 記号AI | ルール・知識グラフ | 显式的・硬直的 |
| 深層学習 | 重み学習 | 暗黙的・更新が必要 |
| LLM | コンテキスト学習 | 推論時即座に取得・自然語で表現 |

コンテキスト学習は、パラメータ更新なしで推論時に新情報を取り込める点で革命的だった。しかし、この利点は**コンテキスト窓の容量**という硬い制約と表裏一体である。

### Agent Skillの台頭と限界

近年、Agent Skillsが再利用可能な領域知識をLLMエージェントに与える主流の方式となった（Anthropicの実装など）。スキルパッケージ $s = (d, m, R)$ は、記述 $d$、指令ファイル $m$（SKILL.md）、資源集合 $R$ からなる。

呼び出し時、Agent SkillはSKILL.mdを**主コンテキストに読み込む**だけだ。実行自体は主エージェントの通常ステップとして行われる。ここに問題がある──読み込んだ知識が蓄積するほど、**推論品質が劣化**する。長期タスクではこの劣化が致命的になる。

### Subagentという代替案

Subagent実行は、スキルの指令を主コンテキストに読み込む代わりに、**新規のコンテキスト窓を起動**し、そこでスキルを独立に実行する。結果だけを主エージェントに返す。

すでにClaude CodeやOpenAI CodexはSubagentをサポートしているが、主に**タスクの並列化**に使われており、**情報カプセル化**の観点からの研究は不足していた。本稿はこの盲点を突く。

## 方法詳解：二つの実行方式の定式化

### Agent Skill実行

ツール呼び出し言語モデルエージェントの反復実行プロセスにおいて、Agent Skillの呼び出しは次のように定義される：

$$E(k = \mathrm{AgentSkill}(s), \varnothing) = m_k$$

これはSKILL.mdの内容 $m_k$ を主コンテキストに返すだけだ。以降、主エージェントは $m_k$ の指示に従って行動するが、**すべてのステップが同一の主コンテキスト内で実行される**。コンテキストは単調増加し、スキルの指令もその中に留まり続ける。

### Subagent実行

Subagent実行は、技能ごとに**独立した方策**を定義する：

$$\pi^{(k)}(\cdot) \triangleq \pi_{LLM}(m_k \oplus \cdot), \quad c^{(k)}_0 = x_t$$

初期コンテキスト $c^{(k)}_0$ は入力 $x_t$ で初期化され、スキルの指令 $m_k$ が文脈の先頭に置かれる。実行後、**最終ステップの応答だけ**が返される：

$$E(k = \mathrm{Subagent}(s), x_t) = r^{(k)}_T$$

### 決定的な違い

| 特徴 | Agent Skill | Subagent |
|------|------------|----------|
| 方策 | 単一方策 $\pi_{LLM}$ | 技能ごとに独立方策 $\pi^{(k)}$ |
| コンテキスト | 単一の主コンテキスト | 独立したコンテキスト窓 |
| 情報の可視性 | すべての情報が可視 | 入力と出力のみで通信 |
| 知識の作用 | 主方策を条件づける | 子方策を条件づける |

![コンテキスト圧力に対する実行方式の頑健性](/images/subagents-vs-agent-skills/fig1.png)
*図1：コンテキスト圧力（ダミースキル数）の増大に対する実行方式の頑健性。Subagent実行は劣化がより緩やか。*

### ピークコンテキスト長の削減

重要なのは、**総コンテキスト消費量**ではなく**ピークコンテキスト長**（いずれかの窓が処理する最大情報量）だ。LLMの推論能力はコンテキスト長に伴い低下する。帯域制限された注意機構が、長い入力中で伝達できる情報量には上限があるからだ。

Subagentはタスクをより小さな自己完結的なサブタスクに分解し、各々を独立した窓で実行する。サブタスク内部の軌跡は主エージェントから隠蔽され、最終出力のみが可視となる。結果として、主エージェントが推論すべき情報量が減り、推論品質が保たれる。

### 入出力契約──オプションフレームワークとの類推

Subagentを有効に働かせるためには、主エージェントが（1）適切なSubagentを同定し、（2）十分な情報を供給できなければならない。本稿はこの条件を、強化学習の**オプションフレームワーク**との類推で定式化する。

オプション $\omega = (\mathcal{I}_\omega, \pi_\omega, \beta_\omega)$ とスキルパッケージ $s = ((q_{\mathrm{in}}, h, q_{\mathrm{out}}), m, R)$ の対応：

| オプション要素 | 契約対応 | 役割 |
|--------------|---------|------|
| $\mathcal{I}_\omega$（開始集合） | $q_{\mathrm{in}}$（入力契約） | Subagentを呼び出せる条件を規定 |
| $\pi_\omega$（オプション方策） | $m$（指令ファイル） | 入力を出力に変換する手続きを符号化 |
| $\beta_\omega$（終了条件） | $q_{\mathrm{out}}$（出力契約） | Subagentが返す内容を制約 |

![オプションフレームワークとスキルパッケージの対応関係](/images/subagents-vs-agent-skills/fig4.png)
*図2：RLのオプションフレームワークとスキルパッケージの構造的対応。契約の明示化が有効なSubagent実行の前提条件となる。*

**核心の仮説**：手続的指令 ＋ 明示的な入出力契約 → 有効なSubagent実行

## 実験結果

### 実験設定：SkillsBench

SkillsBench（Li et al., 2026b）は、エージェントスキルの有効性を評価する専用ベンチマークで、**87個の長期タスク**が複数ドメインにまたがる。各タスクには人手で作成されたスキルパッケージが付属する。OpenHands（Wang et al., 2025）をエージェントフレームワークとして用いる。

### 手続的スキルパッケージの合成

元のSkillsBenchスキルパッケージは、有効なSubagent実行の条件（明示的な入出力指定）を満たさないことが多かった。そこで、GPT-5.3 Codexで3回の独立実行を行い、成功軌跡からCopilot CLIを使って**手続的＋契約駆動のスキルパッケージ**を合成した。87タスク中64タスクで合成に成功し、以下の結果はこの64タスクに基づく。

### スキル設計 × 実行方式の相互作用

![スキル設計と実行方式の相互作用](/images/subagents-vs-agent-skills/fig3.png)
*図3：スキル設計と実行方式の相互作用。手続的＋契約ありの合成スキルでSubagent実行が最も優れる。*

結果は明確だ：

- **策定スキル（非手続的・契約なし）**：Agent Skill実行がSubagent実行に匹敵かそれ以上
- **合成スキル（手続的・契約あり）**：Subagent実行がAgent Skill実行を有意に上回る
- **较小モデルほどSubagentの恩恵が大きい**（帯域制限がより厳しいため）

これは直感に反する結果ではない。構造の緩い知識は主コンテキストに直接注入したほうが、Subagentの入出力インターフェースを通すより効率的に利用できる。一方、明確なインターフェースを持つ手続的知識は、独立した窓で実行することでコンテキスト汚染を回避できる。

### コンテキスト圧力に対するスケーラビリティ

ダミーツール（タスクの解法に不要なツール）を増やし、コンテキスト圧力をシミュレートした。Subagent実行は、ダミーツール数の増加に対して**劣化がより緩やか**だった。ピークコンテキスト削減の効果──すでに大きいコンテキストから技能指令を除外することが、さらに重要になるからだ。

### ピークコンテキスト長とトークンコスト

![ピークコンテキスト削減率とトークン消費の比較](/images/subagents-vs-agent-skills/fig2.png)
*図4：左：Subagent実行によるピークコンテキスト削減率。右：総トークン消費の比較。*

**ピークコンテキスト削減**：強モデル（GPT 5.3 Codex, Kimi K2.6）では、**80%以上**のタスクでSubagent実行がピークコンテキスト長を削減した。弱モデルでは削減幅が小さく、時には逆転する──Agent Skill実行で推論が劣化して**早期終了**するため、コンテキストが短く保たれるからだ。

**トークンコスト**：Subagent実行の総トークン消費は**1.3〜1.8倍**に増加する。情報をSubagent間で重複して伝達するためだ。これは、ピークコンテキスト削減を得るためのトレードオフである。

## 考察

### モジュラリティの強制としてのSubagent

Subagent実行は、情報流を制御する**モジュラリティの強制機構**と解釈できる。明確なインターフェースでタスク固有の知識をカプセル化することで、主エージェントの推論負荷を減らす。これはソフトウェア工学のモジュール設計と同じ発想だ。

### Agent Skillの「アンダーシンキング」現象

Subagent実行では、すべての基礎LLMにおいてスキル呼び出し回数が増えた。Agent Skill実行では、コンテキスト増大に伴いLLMが「十分に思考しなくなる」（underthink）傾向があり、平均的なスキル呼び出し回数が減る。この振る舞いは、コンテキスト圧力が推論の質だけでなく**推論の深さ**にも影響することを示唆している。

### 契約設計の実践的含意

手続的＋契約駆動のスキルパッケージを、**成功軌跡から合成**できることは実践上重要だ。ゼロから理想的なスキルパッケージを設計するのではなく、エージェントの成功例から後成的に契約を抽出できるなら、Subagent実行の適用範囲が広がる。

### 限界

- 既存の策定スキルが手続的＋契約の要件を満たすとは限らない
- Subagent実行は追加の通信コストを生む
- 複数のスキル知識を組み合わせてサブタスクを解く能力が失われる

## 関連研究

### ツール呼び出しエージェント

ReActが推論とツール使用の交替を実装して以来、Toolformer、Gorilla、ToolLLMなどがツール使用の微調整を探求した。HuggingGPTはLLMをツールとして扱い中央制御器で編成するが、スキルパッケージの実行方式は研究していない。τ-Benchとτ²-Benchは長期の状態付き交互を評価するが、再利用可能知識の実行メカニズムには触れない。

### LLMスキル学習

VoyagerはMinecraftエージェントで実行可能コードのスキルライブラリを構築した。LATM、CREATOR、CRAFTはLLMに再利用可能なコードツールを書かせる。EvoSkill、CoEvoSkills、Trace2Skillは軌跡からスキルパッケージを掘り起こす。しかし、これらはすべて**Agent Skill方式で実行**する。本稿は同じスキルパッケージを使いながら、特定の設計のもとでSubagent実行が有効かつスケーラブルであることを示した。

## まとめ

本稿は、再利用可能な知識をLLMエージェントに実行させる二つの方式──Agent Skill実行とSubagent実行──を体系的に比較した。主な知見は：

1. **コンテキスト過負荷でSubagentが有利**：劣化がAgent Skillより緩やか
2. **前提条件は明示的な契約**：手続的知識＋入出力契約があるときのみSubagentが有効
3. **ピークコンテキスト vs 総トークン**：Subagentはピークを削減するが総コストは増加
4. **ハイブリッドが最適**：ルーティングはAgent Skill、葉スキルはSubagentの組合せが一貫して最良
5. **モジュラリティの観点**：Subagent実行は強制的なモジュール化──明確なインターフェースで知識をカプセル化し、情報流を制御する

知識の内容だけでなく、その**組織化と呼び出しの方式**が効用を決める。この洞察は、スケーラブルなエージェントシステムの設計において、単に多くのスキルを蓄積するだけでなく、それらをどう構造化し、どう実行するかが本質的に重要であることを示している。
